# Roadmap: Project Reorganization (Full)

## Goals
- align the repo with a durable, large-project layout
- reduce root clutter and make scripts/reports easier to navigate
- update paths in code/docs so the build remains stable
- keep a clear audit trail (PROJECT_MAP, changelogs)

## Steps
1. Inventory the current structure and path dependencies.
2. Propose a target directory layout and a move map (old → new).
3. Update code/doc references to the new paths.
4. Move files/directories, remove empty folders.
5. Update PROJECT_MAP and copilot-instructions tone.
6. Verify (pytest + manuscript build).

## Success Criteria
- all moved paths are updated in scripts/docs
- manuscript build and key scripts still run
- root is clean; scripts and reports are grouped logically
- PROJECT_MAP matches the new structure

## Risks
- hard-coded paths in scripts/docs could break
- external references might rely on old paths

## Notes
- avoid moving training/inference source code structure unless necessary
- keep reports_ARCHIVE grouped by artifact type
